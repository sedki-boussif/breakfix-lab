Source `lab.conf` rather than writing the URLs into the script: `. /path/to/lab.conf` then use `$STAGES_URL`, `$LEAVES_URL`, `$NURSE_API`. Nothing in this lab hard-codes a URL, and the reason is that the ports move when an app changes mode.
Capture curl's status instead of letting it fail: `code="$(curl -s -o /dev/null -w '%{http_code}' --max-time 5 "$url" || true)"`. With `-f` and `set -e` and no `|| true`, a connection refused ends the script at the first application and the other two are never checked — which looks like a working failure path and is not.
`%{http_code}` is `000` when the connection never happened at all, which is worth distinguishing from a 500 in the output: one is "nothing is listening", the other is "something answered badly", and they send you to different places.
Always set `--max-time`. A check script with no timeout hangs on exactly the day you need it, because a half-open connection is not a refused one and will wait for the default two minutes per application.
Read the thresholds as `"${APPCHECK_DISK_PCT:-80}"` and `"${APPCHECK_MEM_MIN_MB:-256}"`. That one piece of syntax is what makes the warning path testable — the check sets them to values that must trip, and a hard-coded 80 cannot be made to warn on a machine with a 17% disk.
Accumulate the exit status rather than returning early: `rc=0` at the top, `rc=1` on each failure, `exit "$rc"` at the bottom. Returning early means the output stops at the first problem, and the first problem is rarely the only one.
For the timestamp, `date '+%Y-%m-%dT%H:%M:%S'` in a tiny function is enough, and putting it in a function means the format is in one place when you decide you want the timezone too.
