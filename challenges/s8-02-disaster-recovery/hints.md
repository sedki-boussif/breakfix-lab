Before you delete anything, prove the backups are reachable from somewhere that is not this VM: `sudo restic -r "$BACKUP_REMOTE" --password-file "$BACKUP_PASSWORD_FILE" snapshots` has to list something, and `findmnt --target "$BACKUP_REMOTE"` has to show a filesystem that is not `/`. If either fails, this is not a drill yet.
The password file is not in the repository — that was s7-01's second property — which means it is also not in the backups. If `BACKUP_PASSWORD_FILE` only ever existed on the VM you deleted, the archive is encrypted with a key that no longer exists anywhere. Check now, not at minute forty.
Rebuild in s8-01's order, with one change: restore the data instead of seeding it. `restic restore latest --target /` puts files back where they came from; for the databases, restore the dump to a scratch path and load it with `psql` or `pg_restore` rather than restoring over a running data directory.
Restore the fingerprint file too, and look at it before you load anything: it is the only record of what the row counts are supposed to be, and the check compares every line of it against what you end up serving.
If a count comes back short, the restore is not wrong — the archive is older than the rows. That gap is your loss window, it is a real number, and the report asks for it because an RPO nobody measured is the same kind of guess as an RTO nobody measured.
Keep a list as you go of every step you had to work out rather than read. That list is the actual output of this drill — more useful than the elapsed time — and it is the input to s8-03, which takes the runbooks away from everything except themselves.
