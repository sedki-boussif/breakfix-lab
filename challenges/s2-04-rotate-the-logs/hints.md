The layer is logrotate's configuration directory, and the quickest orientation is reading a rule that already works: `cat /etc/logrotate.d/nginx` or `/etc/logrotate.d/rsyslog`. Both are short, both are production rules, and one of them shows you a `postrotate` block for exactly this problem.
The tool for checking your work without waiting a day is `sudo logrotate --debug /etc/logrotate.d/leaves`. It parses the rule, prints the effective settings — "after 1 days (7 rotations)" — and does nothing. `--force` is what actually rotates, and `--verbose` with it tells you each step.
What `--debug` will show you is whether logrotate agrees with what you think you wrote. If your rule is not listed at all when you run `sudo logrotate --debug /etc/logrotate.conf`, the file is not being included: logrotate skips files whose names carry certain suffixes, and in some versions any filename containing a dot.
Now the part that is actually difficult. Rotate it with `--force`, then make a request to the app, then look at the log: if it is still zero bytes, the rotation worked and the application did not notice. A process holds an open *file*, not a filename, so renaming the file under it changes nothing from its point of view.
`sudo ls -l /proc/$(pgrep -f gunicorn | head -1)/fd/` is how you see it: one of those links will point at your log with `(deleted)` after it. That is where the application is still writing, the space is still being used, and nothing will ever read it again.
Two fixes, genuinely different. `postrotate` with `systemctl kill -s USR1 leaves.service` tells gunicorn to reopen its files — precise, and it depends on the application cooperating. `copytruncate` copies the file aside and truncates the original, so the handle stays valid — simpler, works with anything, and loses whatever was written between the copy and the truncate. Pick one, and write down why.
Add `missingok` and `notifempty` while you are there. Without the first, logrotate complains every day until the file exists; without the second, it rotates empty files and you end up with seven empty archives and no data.
