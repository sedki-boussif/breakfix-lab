Every one of the six numbers is in a file or a command that gives it to you plainly: `/proc/uptime`, `/proc/loadavg`, `/proc/meminfo`, `df -P /`, `ps`. The skill being practised is reaching for the machine-readable source rather than parsing the human-readable one.
`/proc/uptime` holds two numbers and the first is seconds since boot, already a number. `uptime` the command produces prose — "up 2 days, 3:14" — whose format changes depending on how long the machine has been up, which is why a regex over it works until it does not.
`/proc/loadavg` is five fields: the three load averages, the running/total process count, and the last PID. The one-minute figure is field 1.
`df -P /` is the portable form, and `-P` is the part that matters: without it a long device name wraps onto two lines and `awk 'NR==2'` reads half a row. The percentage has a `%` on it that `gsub("%","",$5)` removes.
For memory used, `/proc/meminfo` has `MemTotal` and `MemAvailable` in kilobytes, and `MemTotal - MemAvailable` is the figure that answers "how much of this machine is in use". `free`'s `used` column counts buffers and cache as used, which is why a healthy Linux box looks alarming through it. Divide by 1024 for megabytes, and say in the report which definition you chose.
`ps -eo comm,rss --sort=-rss --no-headers` gives you name and resident size, already sorted, largest first — `rss` is in kilobytes. Letting `ps` sort is better than piping to `sort -rn`, because `ps` knows the column is numeric and does not care about alignment.
Run `shellcheck` on it before the check does. Quote every expansion, and remember that `set -u` turns an unset variable into an error rather than an empty string — which is the entire reason it is in the standard.
